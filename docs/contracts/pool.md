# Native pool contract

This contract defines the boundaries of the native SV1/SV2 pool, its durable PPLNS ledger, and the external payout-signing interface. The [operator guide](../pool.md) describes configuration and management RPC usage.

The key words **MUST**, **MUST NOT**, **REQUIRED**, **SHOULD**, **SHOULD NOT**, and **MAY** express requirement levels as defined in [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119.txt). They govern this implementation contract; they do not claim complete Stratum specification coverage or external miner interoperability.

## Owners

| Boundary | Authoritative owner | Responsibility |
| --- | --- | --- |
| Operator options | `crates/node/src/options.rs`, `config.rs` | Feature/runtime gating, explicit configuration, and validation. |
| Composition and shutdown | `crates/node/src/lifecycle.rs`, `pool.rs` | Ledger construction, RPC handle publication, listeners, reconciliation, and draining. |
| Jobs and SV1 | `crates/mining/src/pool/job.rs`, `pool/core.rs`, `pool/stratum/sv1.rs` | MiningControl-backed jobs, share validation, bounded admission, and SV1 protocol handling. |
| SV2 protocol | `crates/mining/src/pool/stratum/sv2.rs` | Noise responder, mining channels, job/share frames, and deferred acknowledgements. |
| Node SV2 adapter | `crates/node/src/pool/sv2.rs`, `authority.rs` | Socket lifecycle, account mapping, found-block handling, and authority-file security. |
| Accounting | `crates/mining/src/pool/ledger.rs`, `ledger/store.rs`, `ledger/kv.rs` | PPLNS work, round/batch transitions, balance conservation, audit records, and versioned payout codecs over `KvStore`. |
| Applied-chain observations | `crates/node/src/pool/ledger.rs` | Hash-keyed canonicality, coinbase bodies, payout transaction/spend observations, and stable reconciliation. |
| Management API | `crates/rpc/src/handlers/pool.rs` | Authenticated key-free accounting operations through the composed pool handle. |

## Clauses

### `POOL-01`: Explicit enablement and operator configuration

- The service MUST be off by default. The `pool` build feature MUST NOT enable the runtime implicitly. SV2 additionally requires `pool-sv2`.
- Enabling the runtime MUST require a nonempty dedicated pool data directory, at least one explicit listener, an exact plain-decimal share difficulty, a positive work window, and a reward script. Node mining MUST also have a payout address.
- The operator MUST configure the node mining payout address and ledger reward script consistently. The ledger MUST NOT infer ownership or redirect a coinbase from the reward-script setting.
- Listener ports MUST be nonzero. SV1 and SV2 addresses MUST differ. A non-loopback listener MUST require `pool_allow_non_loopback`; omission MUST NOT imply permission.
- SV2 bind and authority-file path MUST be configured together. Pool sub-options MUST NOT be silently ignored when the runtime is disabled.
- The node MUST reject maturity below 100, zero payout confirmations, fees above 10,000 basis points, and a reorg watch shorter than maturity, payout confirmation depth, or the fixed six-confirmation abandon depth.
- A reward script MUST be nonempty, bounded to 10,000 bytes, minimally encoded, and not begin with `OP_RETURN`. Passing these checks MUST NOT be represented as proof of spendability or control by the operator.
- Proof: `crates/node/tests/unit/config/tests.rs::pool_defaults_off_and_suboptions_require_enablement` proves the service resolves to no pool by default and rejects pool sub-options when the runtime is disabled. `::pool_requires_explicit_policy_and_listener` proves a nonempty datadir, an explicit listener, a share difficulty, a positive work window, a reward script, and a node mining payout address are each required. `::pool_non_loopback_requires_explicit_opt_in` proves a non-loopback bind requires explicit opt-in and that port zero is rejected. `::pool_money_depth_and_capacity_bounds_are_validated` proves rejection of maturity below 100, zero payout confirmations, fees above 10,000 basis points, a shallow reorg watch, non-positive or inverted connection caps, and `OP_RETURN` or non-minimally-encoded reward scripts. `::pool_exact_difficulty_and_script_parsing_reject_invalid_inputs` proves plain-decimal difficulty and minimally-encoded nonempty script parsing. `::pool_sv2_requires_feature_and_paired_authority_path_without_opening_it` proves the SV2 bind and authority path must be paired, SV1 and SV2 binds must differ, and resolution never opens the key file. `crates/mining/tests/support/pool_ledger_cases.rs::config_validation_rejects_every_unsafe_value` proves ledger-side rejection of zero window work, excess fees, zero maturity, a shallow watch depth, zero dust, an `OP_RETURN` pool script, and empty change scripts.

### `POOL-02`: Schema consent, storage, and immutable policy

- The additive `PoolLedger` storage family and local integration have explicit approval. This approval does not authorize deployment or an existing-data cutover.
- Backend verification MUST use disposable stores, including old-schema fixtures. This work MUST NOT open or migrate existing operator databases. Existing-data cutover requires separate approval.
- The pool MUST use the selected node storage backend through the storage-owned `KvStore` boundary. The ledger MUST NOT acquire a direct engine dependency or reset an existing database implicitly.
- The service MUST lock the dedicated pool directory. It MUST create a ledger only when absent and reopen an existing ledger with the persisted immutable policy checked for equality.
- Accounting policy changes MUST NOT silently reinterpret historical shares or funds. A configuration mismatch MUST fail rather than delete or recreate the ledger.
- Ledger creation/opening and run-epoch allocation MUST precede listener admission. A run epoch MUST distinguish restarted protocol job identities in durable share accounting.
- Proof: `crates/mining/tests/support/pool_ledger_cases.rs::create_refuses_existing_paths_and_open_demands_the_same_config` proves the ledger is created only when absent and reopening with a different window, fee, or any persisted immutable policy fails with `ConfigMismatch` instead of deleting or recreating. `::open_refuses_a_foreign_store_without_writing_to_it` proves opening a store holding foreign content fails with `NotALedger` while leaving the foreign bytes intact and writing no `pool-ledger/v1/` keys. The `redb` and `fjall` modules in `crates/mining/tests/pool_ledger.rs` run the whole suite through `Arc<dyn KvStore>` against both real node storage engines, which exercises the storage-owned boundary. `::runtime_epochs_are_durable_and_shared_between_ledger_handles` proves run-epoch allocation is monotonic across handles and restarts, while `crates/node/src/pool/tests.rs` (`redb`/`fjall::restart_epoch_prevents_reused_wire_job_identity_collision`) proves the new epoch separates a reused wire job identity after restart and `redb`/`fjall::accepted_share_has_exact_durable_identity_and_idempotent_replay` proves the exact durable share identity survives reopen. `crates/node/src/pool/tests.rs::pool_prepare_holds_directory_lock_for_service_lifetime` proves the real `PoolService::prepare` path (opened `NodeState`, pool-enabled config) holds the dedicated pool-directory lock for the service lifetime and releases it on drop, while `::pool_directory_lock_is_exclusive_while_prepare_resources_live` pins the underlying exclusivity. `::pool_prepare_create_open_and_epoch_run_under_the_directory_lock_redb` and `::pool_prepare_create_open_and_epoch_run_under_the_directory_lock_fjall` prove ledger creation/opening with the persisted-policy equality check plus run-epoch allocation run under that same held lock through the exact `LedgerComposer`/`open_generic` prepare path, with a changed policy failing as `ConfigMismatch`. Residual gap: listeners starting only after RPC bind plus an initial template, and shutdown draining, are not covered; they need a pool-enabled `start_node` (hand-built `PoolConfig` with matching share target plus a template-serving mining control) and remain structural in `crates/node/src/lifecycle.rs`.

### `POOL-03`: Shared admission and bounded deferred work

- SV1 and SV2 MUST use one shared total/per-IP connection limiter. Defaults are 128 total connections and 8 per IP. Both limits MUST be positive, and the per-IP limit MUST NOT exceed the total.
- Runtime job retention MUST be bounded at 64 jobs, owner sessions at twice the configured connection cap, and duplicate-share tracking at 65,536 entries per job. Owner sessions are not the same budget as live TCP connections.
- The node-composed deferred share-ledger outbox MUST be bounded by both 1024 records and 8 MiB. Exhaustion MUST reject work before validation. SV1 MUST withhold success for queued writes until their accounting completion is recorded.
- Found-block processing MUST reserve capacity before SV2 protocol feed/validation can emit work requiring a record. Found-record reservations and recovery records MUST share the eight-slot budget, with a 4,000,000-byte charge per slot. Failed writes MUST retain the compact accounting projection rather than serialized full blocks.
- Per-connection protocol limits MUST remain in force in addition to aggregate admission. None of these individual bounds is a claim of a total-process memory bound.
- Proof: `crates/mining/tests/pool_sv1.rs::shared_connection_limiter_enforces_total_and_per_ip_caps` proves total and per-IP caps with release on drop, and `crates/node/src/pool/tests.rs` (`protocol_admissions_share_total_capacity_and_release_it_on_drop`, `protocol_admissions_share_per_ip_capacity_without_consuming_refused_slots`) proves SV1 and SV2 share one limiter and refused admissions consume no slot. `crates/mining/tests/pool_sv1.rs::connection_caps_refuse_excess_peers_and_shutdown_joins_served_sessions` proves excess peers are refused and shutdown joins served sessions. `crates/mining/tests/pool_jobs.rs::retention_is_bounded_and_retired_jobs_are_stale` proves bounded job retention with stale rejection of evicted jobs; `::sessions_get_unique_bounded_prefixes_and_reuse_oldest_freed_first` and `::unusable_configurations_are_refused` prove bounded owner sessions and refusal of zero capacities. `::rejected_input_cannot_fill_the_duplicate_set_and_capacity_never_refuses_a_block` and `::block_candidate_at_job_capacity_is_remembered_as_duplicate_on_replay` prove rejected input does not fill the per-job duplicate set while a block accepted at capacity is still remembered. `crates/mining/tests/pool_sv1.rs::transactional_outbox_buffers_shares_when_ledger_fails`, `::configured_minima_cannot_fail_an_empty_outbox`, and `::per_submit_reservation_does_not_cap_the_pool_at_one_share` prove the bounded deferred outbox withholds success until the durable record and admits submits on an empty outbox without capping the pool at one share; `block_record_capacity_is_bounded_and_permit_drop_releases_it` (node pool tests, both backends) proves the eight found-record slots with release on drop. `crates/mining/tests/pool_sv2.rs::unconfirmed_shares_are_bounded_and_a_busy_refusal_is_not_recorded` proves the per-connection pending-ack bound with a `pool-busy` refusal that records nothing. `crates/node/tests/unit/config/tests.rs::pool_composed_connection_defaults_are_pinned` proves resolution pins the composed 128-total / 8-per-IP connection defaults, `crates/mining/tests/pool_sv1.rs::composed_pool_defaults_enforce_total_and_per_ip_caps` proves a (128, 8) limiter admits exactly 128 total with 8 per IP and releases on drop, and `crates/node/src/pool/tests.rs::composed_core_bounds_pin_the_contract_literals` proves the composed core carries 64 retained jobs, sessions at twice the connection cap, 65,536 duplicate-tracked entries per job, and a 1024-record / 8 MiB deferred outbox.

### `POOL-04`: Authority-key handling

- The SV2 authority MUST be a matching BIP340 x-only public/secret keypair. It authenticates the mining transport and MUST NOT be treated as payout custody.
- On Unix the key file MUST be a regular file with permission bits exactly `0600`. Opening MUST use `RDONLY`, `CLOEXEC`, `NOFOLLOW`, and `NONBLOCK`, followed by validation of the opened descriptor's metadata. A final-component symlink or special file MUST NOT bypass this check.
- The file MUST contain exactly two ASCII-whitespace-separated 64-digit hexadecimal fields, public key first and secret key second. Input larger than 256 bytes or extra fields MUST be rejected.
- Secure authority-file loading MUST fail closed where this implementation has no supported loader; the non-Unix path reports unsupported operation.
- The file input buffer, decoded secret buffer, and stored authority secret MUST use zeroizing ownership. Debug formatting MUST redact the stored secret, and parse errors MUST NOT include key input. This requirement does not certify zeroization of cryptographic dependency internals, kernel buffers, or every transient machine-level copy.
- Operators SHOULD protect ancestor directories. `NOFOLLOW` on the opened path MUST NOT be described as an ancestor-directory trust guarantee.
- Proof: `crates/mining/tests/pool_sv2.rs::noise_handshake_authenticates_the_pool_to_a_pinned_miner` proves the authority authenticates the Noise transport to a miner pinning its public key; `::a_miner_pinning_another_authority_rejects_the_server_certificate` proves a certificate from another authority is rejected; `::a_mismatched_authority_key_pair_is_refused_at_accept` proves a non-matching public/secret pair is refused at accept. `crates/node/src/pool/authority.rs::tests::load_accepts_exactly_two_hex_fields_in_a_0600_regular_file` proves a two-field `0600` regular file loads with the expected public key and a `<redacted>` `Debug` that carries no secret hex; `::load_tolerates_surrounding_ascii_whitespace_but_nothing_else` and `::load_rejects_inputs_larger_than_256_bytes` prove the exactly-two-64-hex-field and 256-byte limits; `::parse_errors_carry_no_key_input` proves parse errors carry no key input in either `Display` or `Debug`; `::load_enforces_regular_file_and_0600_descriptor_checks` proves non-`0600` modes and directories are refused as `InsecureFile`; and `::load_refuses_a_final_component_symlink` proves a final-component symlink cannot bypass the descriptor check. Residual gap: the non-Unix fail-closed path cannot execute on Linux, and zeroization of transient machine-level copies beyond the `Zeroizing` file/secret buffers and the redacted `Debug` is not observably pinned.

### `POOL-05`: One mining owner and acknowledgement boundaries

- Both protocols MUST derive jobs and validate work through the shared native pool owner backed by `MiningControl`. Protocol adapters MUST NOT introduce a second template or consensus validator.
- A found block MUST be submitted through node mining control before its accounting record is finalized. Submission outcome MUST NOT substitute for active-chain evidence. Applied, duplicate, rejected, missing-parent, and unavailable submission results do not by themselves authorize a reward.
- After an `Applied` block receipt, the shared active job MUST be retired synchronously: `PoolCore::submit_block_to_node` on the SV1 path and `handle_events` on the native SV2 path MUST call `invalidate_active` before ledger, outbox, or transport acknowledgement. Distinct work naming a retired job MUST be rejected as stale; a byte-identical replay of an already accepted header MUST keep its duplicate identity (SV1 21 versus 22; SV2 `stale-share` versus `duplicate-share`) and MUST NOT receive a second credit.
- An exact `inconclusive-not-best-prevblk` receipt on an already in-flight sibling MUST still complete its durable block/share record and then be answered as a nonfatal stale error. Any other node rejection MUST NOT be answered as stale.
- SV2 `SubmitShares.Success` MUST remain deferred until host confirmation of the durable accounting outcome. An idempotently recorded share MAY satisfy that confirmation; a failed or merely queued record MUST NOT be presented as committed.
- SV1 success MUST wait for a completion token covering the required durable share write and, for a found block, its block-record write. Failed inline writes MAY remain in the bounded volatile outbox, but queueing alone MUST NOT complete the response.
- Each SV1 session MUST retain at most one pending accounting response. Additional submissions while it is pending MUST be rejected before validation with a retryable accounting error. Polling MUST send the deferred success only after accounting completion. Process failure MAY lose queued work before completion, but such work MUST NOT already have received success.
- A found-block accounting record MUST initially be pending and deduplicated by its block/share identity. Retrying a record MUST NOT allocate the same reward twice.
- New job parents, clean-job flags, and submission receipts MUST NOT be used as reorg or maturity evidence.
- Proof: `crates/mining/tests/pool_jobs.rs::found_blocks_reach_the_authoritative_submit_path_and_receipts_map_verdicts` proves found blocks go through the shared `MiningControl` submit path with Applied/Rejected/Undetermined verdict mapping. `crates/mining/tests/pool_sv1.rs::applied_block_retires_job_and_second_submit_is_stale` proves synchronous retirement on `Applied` with a second same-job nonce rejected as stale (SV1 21) and never resubmitted. `crates/node/src/pool/sv2.rs::applied_sv2_block_retires_the_common_job_before_a_sibling_reaches_the_node` proves the native SV2 path retires the common job before a sibling reaches the node. `crates/mining/tests/pool_sv2.rs::stale_sibling_receipt_sends_stale_error_without_closing` proves an `inconclusive-not-best-prevblk` sibling still completes its record and is answered `stale-share` without closing; `::accepted_block_retirement_makes_second_same_job_submit_stale` proves post-retirement submits are stale while `::duplicate_share_is_refused_with_the_official_code` and `::stale_jobs_unknown_jobs_and_closed_channels_use_official_codes` prove byte-identical replays keep their `duplicate-share` identity. `::accepted_share_is_held_until_the_ledger_confirms_then_acknowledged` proves SV2 success waits for host confirmation of the durable outcome, and `crates/mining/tests/pool_sv1.rs::transactional_outbox_buffers_shares_when_ledger_fails` with `::crash_restored_share_still_delivers_its_block_record`, `::permanently_refused_share_is_rejected_without_retry_or_buffer`, and `::unknown_wire_job_rejects_before_the_common_submit_owner` prove SV1 deferred success, duplicate preservation across restart, no retry or buffering of permanent refusals, and rejection before the common owner for unknown jobs. `rejected_block_receipt_persists_pending_round_without_funds` and `failed_block_submission_persists_pending_round_without_funds` (node pool tests, both backends) prove rejected/failed receipts leave the round pending with no funds. `crates/mining/tests/pool_sv1.rs::second_submit_while_accounting_pending_is_shed_before_validation` proves the at-most-one-pending-response SV1 session gate: a second submit while one accounting response is pending is shed before validation with the retryable `Share accounting unavailable` error, the shed share never reaches the ledger, the session's next poll still delivers the deferred first success, and the shed share is never burned so its retry credits normally. `::job_install_with_new_parent_issues_no_ledger_write` proves installing jobs with new parents writes nothing to share accounting. Residual gap: clean-job flags and submission receipts not being consumed as reorg or maturity evidence stays structural; receipts are partly covered above (rejected/failed receipts leave rounds pending with no funds), but flag non-use has no direct executable test.

### `POOL-06`: PPLNS reward and maturity

- A round MUST snapshot its accepted-share work window at the solving share. The window is work-weighted, not a count of connections, accounts, or shares.
- Reward fixing MUST require authoritative canonical observation of the exact found block and its coinbase. The observed coinbase txid and total value MUST agree with the recorded claim. Missing bodies or contradictory observations MUST NOT fabricate a reward.
- Gross pool reward MUST be the sum of observed coinbase outputs with the configured pool script. The fee MUST be computed in integer basis points, rounded down. Net allocations MUST conserve that reward after the fee.
- Available balances MUST be credited only after the configured maturity, using confirmations `tip_height - block_height + 1`. Node configuration MUST keep that threshold at or above 100.
- A registered payout script MUST be required for miner admission. Decimal account IDs MAY include one nonempty worker suffix. Login syntax MUST NOT be represented as cryptographic proof of payout-script ownership.
- Proof: `crates/mining/tests/support/pool_ledger_cases.rs::the_window_slides_across_blocks_and_snapshots_are_frozen` proves work-weighted windows snapshot at the solving share and later shares never change a snapshot; `::window_boundaries_are_exact_in_work_units` and `::short_history_uses_all_work_and_pruning_protects_old_windows` prove exact work-unit boundaries with pruning that protects old windows. `::a_found_block_is_recorded_once_and_pays_nothing_until_the_chain_shows_it` proves idempotent found-block recording with no payment before chain evidence and rejection of conflicting height or value claims. `::rounds_mature_only_after_the_configured_confirmations_on_the_active_chain` proves crediting only after the configured confirmations on the active chain. `::the_pool_fee_comes_from_the_observed_reward_and_allocations_sum_to_net` proves the gross equals the observed reward, the fee is floor-rounded, and allocations sum to net. `::a_claim_the_chain_contradicts_is_surfaced_and_never_applied` proves contradictory coinbase claims surface anomalies and are never applied; `::a_coinbase_that_pays_miners_directly_matures_with_a_zero_pool_reward` proves a coinbase with no pool-script output matures with zero pool reward. `only_explicitly_registered_accounts_can_authenticate_or_credit_shares` (node pool tests, both backends) proves shares credit only for explicitly registered accounts with `42.rig` accepted, bare `42` defaulting its worker, and `43`, `address.rig`, empty, or empty-suffix logins refused; `::payout_scripts_are_validated_and_batches_skip_accounts_without_one` proves payout-script validation.

### `POOL-07`: Hash-keyed reorg reconciliation and conservation

- Active-chain membership MUST be observed by exact block hash. A claimed height is only a lookup hint. Known displaced hashes MUST remain distinguishable from unknown hashes even when the replacement tip is lower or equal.
- The node adapter MUST take stable applied-chain observations. Transaction and spend index hints MUST be checked against the corresponding canonical block body before being accepted as payout evidence.
- A monitored matured round displaced from the active chain MUST become orphaned and reverse its allocations. Reversal MUST consume available funds first; the remainder MUST become a deficit rather than erase a reservation or rewrite an already-paid amount.
- Future credits MUST offset deficits before increasing available funds. Per account, `available + reserved + paid - deficit` MUST equal credited matured-round allocations.
- Unknown membership MUST NOT be treated as proof of canonicality or displacement. Reorg monitoring is bounded: rounds and confirmed batches leave monitoring according to the configured watch horizon. This contract MUST NOT be advertised as unlimited deep-reorg recovery.
- Payout confirmation reversal MUST preserve the batch's financial reservation/accounting transitions. A transaction disappearing from a mempool MUST NOT prove that its signature is unusable or that its inputs cannot later be spent.
- Proof: `crates/mining/tests/support/pool_ledger_cases.rs::equal_height_fork_reverses_matured_credits` and `::lower_height_fork_reverses_matured_credits` prove an equal-height and a lower-height replacement tip both orphan a matured round and reverse its credits with conservation held. `::a_reorg_before_maturity_orphans_the_round_with_nothing_to_reverse_and_can_revive` and `::a_reorg_after_maturity_reverses_the_credits_and_re_credits_when_the_block_returns` prove pre-maturity orphaning with nothing to reverse plus revival, and post-maturity reversal with re-credit on return. `::reversing_credits_that_were_already_reserved_creates_an_explicit_deficit` proves reversal consumes available funds first and the remainder becomes an explicit deficit that later re-credit clears before increasing available funds, keeping `available + reserved + paid - deficit` balanced via `check_invariants`. `::unseen_rounds_stop_being_monitored_after_the_watch_depth` proves bounded monitoring leaves rounds unwatched past the horizon. `::a_claim_the_chain_contradicts_is_surfaced_and_never_applied` and `::reconciliation_is_idempotent_and_writes_no_audit_noise` prove contradictory claims never apply and unknown membership changes nothing idempotently. `::a_reorged_out_confirmation_reverts_the_payout_and_a_new_block_reconfirms_it` and `::a_batch_fails_only_when_every_signed_transaction_is_conclusively_double_spent` prove payout confirmation reversal preserves reservations and transitions, with failure only on conclusively double-spent inputs. `crates/node/src/pool/tests.rs::node_chain_view_reports_missing_index_observer_errors` proves the `NodeChainView` missing-index legs through a real opened `NodeState`: `tx_status` without a txindex and `confirmed_spender` without a script index fail as observer errors rather than evidence of nonpayment or safe abandonment. Explicit blocker: the canonical-body checks of populated transaction/spend index hints have no fixture — they need applied blocks plus populated indexes, which no pool test scope builds.

### `POOL-08`: External signing without wallet custody

- Management pool RPC MUST remain authenticated and key-free. The pool MUST NOT generate, import, expose, or use Bitcoin payout private keys. The external signer MUST own funding, input selection, signatures, and fee policy.
- `preparepayoutbatch` MUST reserve eligible funds with a 32-byte idempotency key. Its policy MUST NOT lower the configured minimum payout or exceed the configured output cap. The absolute maximum is 2500 outputs; the configured minimum is bounded from 546 satoshis through `MAX_MONEY`.
- The signer request MUST use the strict canonical BRPR version 1 codec. The receipt MUST use BRPT version 1. Metadata integers are big-endian. BRPR carries exact payout outputs and authorized change scripts; BRPT carries batch ID, txid, and raw transaction.
- Receipt recording MUST recompute the txid, match the exact payout-output multiset, reject unauthorized extra outputs, reject invalid or duplicate inputs, and preserve reservations on rejection. A replacement MUST conflict with earlier signed transactions of that batch rather than permit independent double payment.
- The generic verifier allows at most one authorized change output. The node policy supplies no authorized change scripts, so node-composed batches MUST reject all extra change outputs.
- Receipt validation MUST NOT be described as signature or input-ownership verification. `recordpayoutreceipt` MUST NOT broadcast. Chain observation of the recomputed txid supplies node-acceptance evidence; payment confirmation additionally requires the configured depth.
- Signing failure, timeout, or receipt rejection MUST NOT release a reservation implicitly. Cancellation MUST require a prepared batch and explicit `never_handed_to_signer` or `signer_revoked` basis. The operator MUST establish that external basis; the RPC cannot prove signer revocation.
- Lack of a transaction index prevents confirmed payout observation outside the mempool; lack of a script index prevents confirmed-spend observation. Such observer errors MUST NOT be converted into evidence of nonpayment or safe abandonment.
- Proof: `crates/rpc/src/handlers/pool.rs::disabled_pool_never_returns_fabricated_success` proves every pool handler is method-disabled without a ledger and returns no fabricated success. `::enabled_handlers_use_the_real_durable_ledger` proves key-free handlers over the real durable ledger with idempotency-key, minimum-payout, and output-cap policy enforcement. `::funded_external_payout_round_trip_preserves_reservations_on_rejection` proves the funded prepare/request/sign/broadcast walk with the reservation preserved across a txid-mismatch rejection and no cancellation after signing. `crates/mining/tests/support/pool_ledger_cases.rs::preparing_a_batch_reserves_balances_atomically_and_never_double_allocates` proves atomic reservation with idempotency-key replay returning the immutable batch; `::payout_policy_is_bounded_by_dust_and_output_limits` proves the 546-sat dust floor and output-cap bound. `::payout_request_and_receipt_round_trip_and_reject_corruption` proves the strict `BRPR`/`BRPT` version 1 codecs with big-endian metadata, exact outputs, and rejection of bad magic, trailing bytes, and truncation; `::config_encode_validates_change_scripts_before_encoding` proves change-script allowlist validation. `::a_signed_transaction_must_pay_exactly_the_batch_and_prove_its_own_txid` proves exact-output/txid matching with reservations preserved on every refusal (wrong txid, null or duplicate inputs, unparseable receipts, unknown batches, excess change outputs); `::replacements_must_conflict_with_every_earlier_signed_transaction` proves replacements must conflict rather than double-pay; `::cancelling_a_prepared_batch_releases_the_reservation_but_never_after_signing` proves cancellation requires a prepared batch with an explicit `never_handed_to_signer`/`signer_revoked` basis and is refused after signing; `::the_external_signer_seam_signs_the_canonical_request_and_failures_change_nothing` proves signer failures change nothing. `::a_payout_walks_prepared_signed_broadcast_confirmed_with_exact_accounting` proves broadcast requires mempool observation and confirmation requires the configured depth. `crates/rpc/tests/auth.rs::pool_management_requires_authentication_and_management_surface` proves the RPC-layer gate over real TCP dispatch: an authorized management request reaches the pool handler (which refuses without an enabled ledger instead of fabricating status), while missing or wrong credentials are refused with 401 and the public surface never routes pool JSON-RPC.

### `POOL-09`: Lifecycle and protocol scope

- Composition MUST construct the ledger/operator handle before management RPC publication. Mining listeners MUST start only after RPC binds successfully and an initial template is available.
- Reconciliation MUST refresh work and observe rounds/payouts without holding shutdown hostage to a future mining generation. Shutdown MUST stop admission, cancel and join protocol workers, and drain bounded deferred accounting work within the node's shutdown deadline. A missed deadline or worker panic MUST remain an error, not a success report.
- SV2 support is limited to the role matrix in `crates/mining/src/pool/stratum/sv2.rs`: Noise responder transport, mining setup version 2, standard and extended channels, a per-connection group, and job/share handling, including the adapter's reconnect API.
- Custom jobs/work selection, Job Declaration, a Template Distribution server, extranonce-prefix changes, and extensions negotiation MUST NOT be advertised as implemented. The in-process template source MUST NOT be confused with a Template Distribution server.
